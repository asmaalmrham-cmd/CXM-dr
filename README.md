# مساعد CXM الذكي (Tool Calling)

## 1. نظرة عامة
شات ذكي بالعربي يجاوب عن بيانات CXM (الفروع، الخدمات، التقييمات، الاستبيانات، التوزيع الديموغرافي، التعليقات).
النموذج **ما يحسب ولا يشوف البيانات**: يفهم السؤال ويختار أداة، الباك ينفذها، والنموذج يصيغ الجواب من النتيجة فقط.

```
المستخدم → POST /select_tool → {tool,args} → الباك ينفذ الأداة → POST /compose_answer → الجواب
```

## 2. النموذج المستخدم
`Qwen/Qwen3-4B-Instruct-2507` (يتغير بمتغير البيئة `MODEL_ID`).

سبب الاختيار (التفاصيل في [وثيقة القرار](docs/model_decision.md)):
- أفضل دقة في تصنيف المشاعر: 94% مقابل 80% لـ Qwen3-8B.
- نفس اختيار الأداة (97.6%) ونفس الجواب النهائي (66%) كـ Qwen3-8B، بذاكرة أقل (5.0 GB مقابل 8.4 GB).
- Qwen2.5-7B استُبعد: الأداة 92.9% والمدخلات 57.1% والجواب النهائي 46%.

## 5. قائمة الأدوات (للباك)
المخرجات بالتفصيل في `tool_impl.py`. الحقل `period` قيمه: `week` (7 أيام) / `month` (30) / `quarter` (90).

| الأداة | المدخلات (* إجباري) | المخرج |
|---|---|---|
| `branches_count` | city, status(active/inactive) | `{"count": 2}` |
| `branches_list` | city, status | `{"count":4,"branches":[{"name","city","status"}]}` |
| `services_list` | — | `{"count":6,"services":["..."]}` |
| `ratings_service_get` | period*, service, sort(top/bottom), limit | `[{"service","avg","responses"}]` |
| `ratings_branch_get` | period*, city, sort, limit | `[{"branch","avg","responses"}]` |
| `ratings_overall` | period*, branch, service | `{"avg":4.41,"responses":63}` |
| `responses_count` | period*, branch, service | `{"count":63}` |
| `demographics_get` | dimension*(age_group/gender/city), period | `{"dimension","total","distribution":[{"group","count","pct"}]}` |
| `ratings_trend` | service, branch | `[{"window","avg","responses"}]` |
| `comments_get` | period*, branch, limit | `[{"text","date","branch"}]` |

عند عدم وجود بيانات يرجع الباك `{"error": "..."}`. **الأرقام والنسب كلها يحسبها الباك** (مثل `pct`)، لأن النموذج ممنوع يحسب.

## 6. طريقة استدعاء الـ API
**الطلب 1 — اختيار الأداة** `POST /select_tool`
```json
{"question": "كم فرع عندنا في جدة؟", "history": []}
```
الرد: `{"type":"tool","tool":"branches_count","args":{"city":"جدة"}}`
أو (توضيح/رفض): `{"type":"reply","text":"تبغى النتيجة لأي فترة؟","options":["آخر أسبوع","آخر شهر","آخر 3 شهور"]}`
لما المستخدم يضغط خيار، الواجهة ترسله كسؤال جديد مع `history` (آخر رسائل المحادثة).

**الطلب 2 — صياغة الجواب** `POST /compose_answer`
```json
{"question": "كم فرع عندنا في جدة؟", "tool": "branches_count", "result": {"count": 2}}
```
الرد: `{"text": "عندك فرعين في جدة."}`
(لأداة `comments_get` الرد يتضمن الملخص + نسب المشاعر + المواضيع.)

```python
import requests
BASE = "https://<space-url>"
sel = requests.post(f"{BASE}/select_tool", json={"question": "كم فرع عندنا في جدة؟", "history": []}).json()
if sel["type"] == "tool":
    result = my_backend_execute(sel["tool"], sel["args"])   # الباك ينفذ الأداة
    ans = requests.post(f"{BASE}/compose_answer",
                        json={"question": "كم فرع عندنا في جدة؟", "tool": sel["tool"], "result": result}).json()
    print(ans["text"])
else:
    print(sel["text"], sel.get("options"))
```

## 7. البرومبتات

النص الكامل في `prompts.py`، وهذا نصها مع سبب اختيار كل واحد.

### 7.1 برومبت اختيار الأداة (`build_select_prompt`)

أنت مساعد ذكي لنظام CXM (إدارة تجربة العملاء). مهمتك الوحيدة: فهم سؤال المستخدم واختيار الأداة المناسبة مع مدخلاتها.
أنت لا تجاوب من عندك ولا تحسب أرقامًا، الأدوات هي اللي تجيب البيانات.

القواعد:
1. استدعِ أداة واحدة فقط لكل سؤال.
2. إذا كان السؤال ناقص مدخل إجباري (مثل الفترة الزمنية)، لا تخمّن: استدعِ ask_clarification مع سؤال قصير وخيارات.
3. إذا كان السؤال ما له علاقة ببيانات النظام (طقس، أخبار، شعر، أسعار...)، استدعِ out_of_scope.
4. افهم الفصحى واللهجات (وش، كم، هالشهر، أبغى، ليش...).
5. الفترات: "هالأسبوع/آخر أسبوع/الأسبوع الماضي" = week ، "هالشهر/آخر شهر" = month ، "آخر 3 شهور/ثلاث شهور" = quarter.
6. "أعلى/أفضل" = sort:top ، "أقل/أضعف/أسوأ" = sort:bottom. "أعلى واحد" = limit:1 ، "أفضل ثلاثة" = limit:3.
7. إذا أجاب المستخدم على سؤال توضيح (مثل "آخر أسبوع")، ارجع للمحادثة السابقة واستخدم السؤال الأصلي مع الإجابة.
8. اكتب أسماء المدن والفروع والخدمات بالعربي كما هي في النظام، وبدون كلمة "فرع" في اسم الفرع.

المتوفر في النظام:
- المدن: {قائمة المدن}
- الفروع: {قائمة الفروع}
- الخدمات: {قائمة الخدمات}
```

**ليش كذا:**
- يحصر مهمة النموذج في **اختيار الأداة والمدخلات فقط**، وما يجاوب من عنده ولا يحسب. هذا يحقق القاعدة الأساسية في المشروع: أي رقم في الجواب لازم يجي من نتيجة الأداة.
- القاعدتان 2 و3 تعطيان النموذج مخرجين غير الأداة: `ask_clarification` للتوضيح و`out_of_scope` للرفض، فما يضطر يخمّن أو يجاوب خارج النطاق.
- القاعدتان 4 و5 و6 تربطان الفصحى واللهجة (وش، هالشهر، أضعف...) بقيم المدخلات الثابتة (`week/month/quarter`، `top/bottom`)، لأن المستخدمين يكتبون بالاثنين.
- القاعدة 7 تخلي النموذج يكمل سؤال التوضيح من سجل المحادثة بدل ما يبدأ من جديد.
- قوائم المدن والفروع والخدمات تُحقن من البيانات نفسها، عشان يكتب الأسماء مثل ما هي في النظام.

### 7.2 برومبت صياغة الجواب (`COMPOSE_SYSTEM`)

```text
أنت مساعد CXM. اكتب جوابًا مختصرًا (من جملة إلى ثلاث جمل) بالعربي الواضح، بناءً فقط على نتيجة الأداة.
قواعد صارمة:
- لا تضف أي رقم غير موجود حرفيًا في نتيجة الأداة. لا تحسب ولا تجمع ولا تقرّب ولا تحوّل.
- لا تخترع أسماء فروع أو خدمات.
- إذا كانت النتيجة فيها خطأ أو فارغة: قل بلطف إنه ما فيه بيانات مطابقة.
- عند عرض قائمة استخدم الشرطة (-) وليس الترقيم.
- لا تذكر الأدوات أو JSON أو تفاصيل تقنية.
```

والتنبيه اللي يُضاف عند إعادة المحاولة (`COMPOSE_STRICT_SUFFIX`):


تنبيه: جوابك السابق احتوى أرقامًا غير موجودة في النتيجة. استخدم فقط الأرقام الموجودة حرفيًا في النتيجة، وإذا ما تأكدت اذكر الأسماء بدون أرقام.
```

**ليش كذا:** يقيّد الجواب بنتيجة الأداة وحدها، ويمنع الحساب والتقريب واختراع الأسماء. الجمل القصيرة تقلل فرصة الخطأ. والتنبيه الصارم يُستخدم فقط لو الكود اكتشف رقمًا مو في النتيجة (انظر 7.5).

### 7.3 برومبتات التلخيص والمشاعر

```text
صنّف مشاعر كل تعليق من تعليقات العملاء إلى واحدة من: إيجابي / سلبي / محايد.
أرجع مصفوفة JSON فقط، بنفس عدد وترتيب التعليقات، بدون أي شرح. مثال: ["إيجابي","سلبي","محايد"]
```

```text
أنت محلل تجربة عملاء. اقرأ تعليقات العملاء ولخّصها.
أرجع JSON فقط بهذا الشكل:
{"summary": "ملخص من جملتين إلى ثلاث بالعربي", "topics": ["موضوع 1", "موضوع 2", "موضوع 3"]}
قواعد: لا تذكر أي أرقام أو نسب أو أعداد في الملخص. اذكر أبرز ما يمدحه العملاء وأبرز ما يشتكون منه. المواضيع من 2 إلى 5، كل موضوع كلمتين أو ثلاث.
```

**ليش كذا:** التصنيف والتلخيص في برومبتين منفصلين، والمخرج JSON فقط ليسهل تحليله. وممنوع الأرقام داخل الملخص، لأن **نسب المشاعر يحسبها الكود** من التصنيفات (انظر 7.5).

### 7.4 النصوص الثابتة

```text
عذرًا، هذا السؤال خارج نطاق بيانات CXM. أقدر أساعدك في أسئلة عن الفروع، الخدمات، التقييمات، الاستبيانات، التوزيع الديموغرافي، وتعليقات العملاء.
ما لقيت بيانات مطابقة لسؤالك. جرّب تغيّر الفترة أو الفرع أو الخدمة.
ما فيه تعليقات في هالفترة أو لهذا الفرع.
```

**ليش كذا:** الرفض وعدم وجود بيانات يطلعان من الكود بنص ثابت، فما يعتمدان على مزاج النموذج.

### 7.5 قرارات التصميم في الكود

- **التحقق من المدخلات (`validate_call`):** مدخل إجباري ناقص ← يسأل توضيح بدل التخمين، وقيمة غلط ← تنصلح أو تنحذف.
- **كلام النموذج الحر في خطوة اختيار الأداة ما يوصل للمستخدم أبدًا**، لأنه ممكن يكون جواب مخترع.
- **فحص الأرقام المخترعة:** لو الجواب فيه رقم مو في نتيجة الأداة ← إعادة توليد مرة بالتنبيه الصارم، وبعدها نعرض النتيجة الخام.
- **نسب المشاعر يحسبها الكود** من التصنيفات، مو النموذج.

### 8.5 القيود المعروفة

- **الأرقام أولية:** تشغيل واحد على Colab بنماذج مضغوطة (4-bit)، وما كررنا التشغيل لقياس التذبذب.
- **المقيّم الآلي تقريبي:** يتأكد من الحقائق الأساسية وغياب الأرقام المخترعة، وفيه حالات خطأ كاذب (مثل Q9 وQ31)، فالأخطاء تُراجع يدويًا.
- **البيانات وهمية:** التعليقات مولّدة ومصنّفة مسبقًا، فدقة المشاعر قد تختلف على تعليقات حقيقية.
- **نسب الملخص تختلف قليلًا عن `eval_sentiment.py`** على نفس التعليقات (مثلًا ملخص 3 شهور: إيجابي 49% مقابل 44% متوقعة من مصفوفة الالتباس)، والسبب المرجّح ترتيب التعليقات في الدفعات، وما اختبرناه بعد.
- **الملخص يعتمد على أول 60 تعليق فقط** (`texts[:60]`)، أما النسب فتُحسب على كل التعليقات.
- **تقييم جودة العربي يدوي وذاتي** (1 إلى 5).
- **الواجهة تدعم** سؤال وجواب مع `history` قصير (آخر 6 رسائل).
- **ما فيه API مستضاف بشكل دائم:** المتاح Static Space فقط، والـ API يشتغل من Colab أو من أي جهاز فيه GPU بـ `python app.py` على المنفذ 7860. ⚠ عدّلي هذا السطر لو تغيّر الوضع.
